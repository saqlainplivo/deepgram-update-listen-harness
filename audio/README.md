# Audio Files

## What's here

| File | Description |
|------|-------------|
| `test_speech.wav` | **Synthetic test audio** — generated by `generate_test_wav.py`. 30 seconds of alternating silence (2 s) and 440 Hz sine tone (2 s). Mono, 16-bit PCM, 16 000 Hz. |
| `generate_test_wav.py` | Script to regenerate `test_speech.wav`. |

## Audio source used in published results

> **Synthetic audio only — no real speech.**
>
> All results published in `results/` were produced with the synthetic
> `test_speech.wav` file described above, **not** a Plivo phone-call
> audio source.
>
> A Plivo SIP trunk was not available in the test environment used for
> the initial run.  If you have a Plivo trunk, you can replace this
> file with real call audio or pass `--audio mic` to stream live
> microphone input.

## Why this matters for interpreting results

The synthetic audio means:

1. **Turn-taking latency figures are real** — `eot_threshold` changes
   and `UpdateListen` round-trip times are genuine WebSocket measurements
   unaffected by audio content.

2. **Keyterm recall figures may be unreliable** — Deepgram STT will
   transcribe the sine-tone as silence or noise, so `pre_recall` and
   `post_recall` will typically both be 0.  To get meaningful keyterm
   accuracy data, replace `test_speech.wav` with a real WAV recording
   of the `--reference` phrase (see README for details).

## How to record your own audio

```bash
# macOS — record 10 seconds of mono speech at 16 kHz
sox -d -c 1 -r 16000 -b 16 audio/my_test.wav trim 0 10

# ffmpeg alternative
ffmpeg -f avfoundation -i ":0" -ac 1 -ar 16000 -sample_fmt s16 audio/my_test.wav
```

Then run the harness with `--audio audio/my_test.wav`.
